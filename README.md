# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
#### Интерфейсы данных
##### Интерфейс IProduct
Описывает данные о товаре.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

- id — уникальный идентификатор товара;
- description — описание товара;
- image — ссылка на изображение товара;
- title — название товара;
- category — категория товара;
- price — цена товара; null, если цена не указана.

##### Интерфейс IBuyer
Описывает данные о покупателе.

```ts
interface IBuyer {
  payment: TPayment | null;
  email: string;
  phone: string;
  address: string;
}
```

- payment — выбранный способ оплаты; null, если способ оплаты ещё не выбран;
- email — email покупателя;
- phone — номер телефона покупателя;
- address — адрес доставки.


##### Интерфейс IProductsResponse
Описывает ответ сервера на GET-запрос с данными каталога.
```ts
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

- total — общее количество товаров;
- items — массив товаров каталога.

##### Интерфейс IOrderRequest
Описывает данные заказа, отправляемые на сервер.

```ts
interface IOrderRequest extends Omit<IBuyer, 'payment'> {
  payment: TPayment;
  total: number;
  items: IProduct['id'][];
}
```

- payment - выбранный способ оплаты; в отличие от IBuyer, здесь null исключен;
- email — email покупателя, наследуется из IBuyer;
- phone — номер телефона покупателя, наследуется из IBuyer;
- address — адрес доставки, наследуется из IBuyer;
- total — итоговая стоимость заказа;
- items — массив id товаров, входящих в заказ.

##### Интерфейс IBasket

#### Типы данных
##### Тип TPayment
Описывает доступные способы оплаты.

```ts
type TPayment = 'card' | 'cash';
```

- 'card' — оплата банковской картой;
- 'cash' — оплата наличными при получении.


##### Тип TValidationErrors
Описывает объект ошибок валидации данных покупателя.
```ts
type TValidationErrors = Partial<Record<keyof IBuyer, string>>;
```

- ключ объекта — одно из полей интерфейса IBuyer;
- значение — текст ошибки для соответствующего поля;
Поле может отсутствовать в объекте, если ошибка для него не обнаружена.

##### Тип TOrderResponse
Описывает успешный ответ сервера после оформления заказа.

```ts
type TOrderResponse = {
  id: string;
  total: number;
};
```

- id — уникальный идентификатор созданного заказа;
- total — итоговая сумма подтверждённого заказа.

##### Тип TCard
Описывает общие данные для всех видов карточек товара.
```ts
    type TCard = Pick<IProduct, 'title' | 'price'>;
```
- title — название товара;
- price — цена товара; `null`, если цена не указана.

##### Тип TCategory
Описывает допустимые категории товаров на основе ключей объекта `categoryMap`.
```ts
    type TCategory = keyof typeof categoryMap;
```
- значение типа соответствует одному из ключей объекта `categoryMap`.

##### Тип TContactsForm
Описывает данные формы контактной информации покупателя.
```ts
    type TContactsForm = Pick<IBuyer, 'email' | 'phone'>;
```
- email — email покупателя;
- phone — номер телефона покупателя.

##### Тип TOrderForm
Описывает данные формы оформления заказа.
```ts
    type TOrderForm = Pick<IBuyer, 'payment' | 'address'>;
```
- payment — выбранный способ оплаты;
- address — адрес доставки.

##### Тип TBuyerChange
Типирует данные события изменения одного из полей покупателя.

```ts
type TBuyerChange = {

  value: string;
```

- field — имя изменённого поля интерфейса `IBuyer`;
- value — новое значение изменённого поля.

#### Модели данных
##### Класс Products
Класс отвечает за получение, хранение товаров, которые можно купить в приложении

Конструктор класса:
- `constructor(protected events: IEvents) {}` принимает объект, реализующий интерфейс IEvents, и сохраняет его для дальнейшего использования методами класса.

Поля класса:
- `private items: IProduct[]` - массив товаров  
- `private selectedItem: IProduct | null` - выбранный товар


Методы класса:
- `setItems(items: IProduct[]): void` - сохраняет массив товаров из параметров метода
- `getItems(): IProduct[]` - получает массив товаров из модели
- `getItemById(itemId: string) : IProduct | undefined` - получает один товар по его id или undefined, если id не найден.
- `setselectedItem(selectedItem: IProduct): void` - сохраняет товар для подробного отображения
- `getselectedItem(): IProduct | null` - получает товар для подробного отображения или null если товара нет.


##### Класс Cart
Класс отвечает за получение, хранение, добавление в корзину и удаление из нее товаров, выбранных покупателем для покупки

Конструктор класса:
- `constructor(protected events: IEvents) {}` принимает объект, реализующий интерфейс IEvents, и сохраняет его для дальнейшего использования методами класса.

Поля класса: 
- `private list: IProduct[]` - хранит массив товаров выбранных покупателем для покупки


Методы класса:
- `getItems(): IProduct[]` - получает массив товаров, которые находятся в корзине
- `addProduct(product: IProduct): void` - добавляет товар, который был получен в параметре, в массив корзины
- `removeProduct(product: IProduct): void` - удаляет товар, который был получен в параметре, из массива корзины
- `clear(): void` - удаляет все товары из корзины
- `getTotalPrice(): number` - получает стоимость всех товаров в корзине
- `getTotalCount(): number` - получает количество всех товаров в корзине
- `hasItemById(itemId: string): boolean` - проверяет наличия товара в корзине по его id, полученному в параметре метода, возвращает true или false. 


##### Класс Buyer
Класс отвечает за получение, хранение, удаление и валидацию данных покупателя, требуемых для оформления заказа в приложении.

Конструктор класса:
- `constructor(protected events: IEvents) {}` принимает объект, реализующий интерфейс IEvents, и сохраняет его для дальнейшего использования методами класса.


Поля класса:
- `private payment: TPayment | null` - вид оплаты `TPayment` или null, если еще не выбран
- `private email: string` - email 
- `private phone: string` - телефон
- `private address: string` - адрес доставки


Методы класса:
- `setData(data: Partial<IBuyer>): void` - сохраняет данные в модель, с возможностью сохранить только одно значение объекта, не удаляя значения других полей.
- `getData(): IBuyer` - получает все данные покупателя
- `clearData(): void` - очищает все данные покупателя
- `validate(): TValidationErrors` - проверяет валидность каждого поля (не пустое, не равно null), возвращает объект типа TValidationErrors, ключ которого - поле класса, а значение - текст ошибки. Если ошибок нет - возращает пустой объект.


### Слой коммуникации
#### Класс ApiService
Класс использует композицию, чтобы выполнить запрос на сервер с помощью метода get класса Api и получает с сервера объект с массивом товаров.


Поля класса:
- `private api: IApi` - экземпляр API-клиента, через который класс выполняет запросы к серверу.


Конструктор: 
- `constructor(api: IApi) {this.api = api;}` - принимает объект, реализующий интерфейс IApi, и сохраняет его для дальнейшего использования методами класса.


Методы класса:
- `getProducts(): Promise<IProductsResponse>` - совершает get запрос на эндпоинт `/product/` и возвращает объект, полученный от сервера, в котором находится массив товаров. 
- `postOrder(data: IOrderRequest): Promise<TOrderResponse>` - совершает post запрос на эндпоинт `/order/` и передаёт в него данные, полученные в параметрах метода, возвращает объект заказа `TOrderResponse`, подтверждающий покупку.

- `close(): void` - закрывает модальное окно, удаляя CSS-класс `modal_active`, и очищает его содержимое.
- `render(data: IModalData): HTMLElement` - отображает переданные данные, открывает модальное окно и возвращает его DOM-контейнер.

### События приложения

Для связи между слоями приложения используется брокер событий `EventEmitter`. Компоненты представления и модели генерируют события, а презентер в `main.ts` подписывается на них и выполняет необходимую логику приложения.

#### События каталога

- `catalog:changed` - генерируется моделью `Products` после изменения списка товаров. Используется презентером для получения актуального каталога, создания карточек товаров и обновления компонента `Gallery`.

- `productCard:selected` - генерируется при клике на карточку товара в каталоге. Передаёт объект выбранного товара `IProduct`. Используется для сохранения выбранного товара в модели `Products` и открытия детальной карточки.

- `productCard:changed` - генерируется при нажатии на кнопку действия в детальной карточке товара. Используется для добавления выбранного товара в корзину или удаления его из корзины. Контекст выбранного товара передаётся при создании callback через `events.trigger`.

#### События корзины

- `basket:selected` - генерируется при нажатии на кнопку корзины в компоненте `Header`. Используется для открытия и отображения актуального содержимого корзины.

- `basket:removeRequested` - генерируется при нажатии на кнопку удаления товара в карточке `CardBasket`. Передаёт объект удаляемого товара `IProduct`. Используется для удаления товара из модели `Cart` и повторного отображения корзины.

- `basket:orderRequested` - генерируется при нажатии на кнопку оформления заказа в компоненте `Basket`. Используется для перехода к форме оформления заказа.

- `cart:changed` - генерируется моделью `Cart` после изменения содержимого корзины: добавления, удаления или очистки товаров. Используется для обновления счётчика товаров в компоненте `Header`.

#### События данных покупателя

- `buyer:changed` - генерируется моделью `Buyer` после изменения или очистки данных покупателя. Используется для валидации данных и обновления состояния форм `OrderForm` и `ContactsForm`.

#### События формы Order

- `orderForm:changed` - генерируется компонентом `OrderForm` при изменении способа оплаты или адреса доставки. Передаёт объект типа `TBuyerChange`, содержащий имя изменённого поля и его новое значение. Используется для обновления модели `Buyer`.

- `orderForm:submitted` - генерируется при отправке формы `OrderForm`. Используется для перехода ко второму этапу оформления заказа — форме `ContactsForm`.

#### События формы Contacts

- `contacts:changed` - генерируется компонентом `ContactsForm` при изменении электронной почты или телефона. Передаёт объект типа `TBuyerChange`, содержащий имя изменённого поля и его новое значение. Используется для обновления модели `Buyer`.

- `contacts:submitted` - генерируется при отправке формы `ContactsForm`. Используется презентером для формирования объекта заказа и отправки данных на сервер.

#### События успешного оформления заказа

- `success:closed` - генерируется при нажатии на кнопку закрытия компонента `OrderSuccess`. Используется для закрытия модального окна после успешного оформления заказа. Данные с событием не передаются.

### Презентер

Презентер реализован непосредственно в основном файле приложения `main.ts`, без создания отдельного класса. Такой подход выбран, поскольку приложение состоит из одной страницы и не требует нескольких независимых презентеров.

Презентер связывает слой данных и слой представления через брокер событий `EventEmitter`. Компоненты представления не обращаются к моделям напрямую: пользовательские действия генерируют события, презентер обрабатывает их, изменяет состояние моделей и передаёт актуальные данные компонентам представления.

В презентере создаются:
- экземпляр `EventEmitter` для обмена событиями между компонентами приложения;
- экземпляры `Api` и `ApiService` для взаимодействия с сервером;
- модели `Products`, `Cart` и `Buyer`;
- компоненты представления `Modal`, `Gallery`, `Header`, `OrderForm`, `ContactsForm` и `OrderSuccess`.

#### Вспомогательные функции презентера

- `renderCardPreview(item: IProduct): void` - создаёт и отображает детальную карточку выбранного товара. Проверяет наличие товара в корзине, устанавливает соответствующий текст кнопки и блокирует кнопку для товара без цены.

- `renderBasket(): void` - получает товары из модели корзины, создаёт для каждого товара экземпляр `CardBasket` и отображает корзину в модальном окне. Передаёт в представление список товаров, итоговую стоимость и возможность оформления заказа.

- `updateBuyer(data: TBuyerChange): void` - общий callback для обработки изменений полей форм заказа и контактов. Передаёт изменённое поле и его значение в модель `Buyer`.

#### Взаимодействие компонентов

При изменении каталога презентер получает товары из модели `Products`, создаёт для них карточки `CardCatalog` и передаёт полученный массив компоненту `Gallery`.

При выборе карточки товара презентер сохраняет выбранный товар в модели `Products` и открывает его детальное представление.

При нажатии на кнопку действия в детальной карточке презентер проверяет наличие выбранного товара в корзине. В зависимости от текущего состояния товар добавляется в модель `Cart` или удаляется из неё, после чего модальное окно детальной карточки закрывается.

При открытии корзины презентер получает актуальные данные из модели `Cart` и отображает их в модальном окне. При удалении товара модель корзины обновляется - корзина отображается заново.

При каждом изменении модели `Cart` презентер получает актуальное количество товаров из модели и обновляет счётчик товаров в компоненте `Header`.

#### Работа с формами заказа

При запросе оформления заказа презентер получает сохранённые данные покупателя из модели `Buyer` и отображает первый этап оформления - форму `OrderForm`.

Изменения полей `OrderForm` и `ContactsForm` обрабатываются общим callback `updateBuyer`, который сохраняет новые значения в модели `Buyer`.

После изменения модели `Buyer` презентер:
- получает актуальные данные покупателя;
- выполняет их валидацию с помощью модели;
- отдельно формирует ошибки для формы заказа и формы контактов;
- определяет, начинал ли пользователь заполнять соответствующую форму;
- обновляет сообщения об ошибках и состояние доступности кнопок отправки;
- обновляет визуальное состояние выбранного способа оплаты.

После успешной отправки `OrderForm` презентер отображает форму `ContactsForm`, подставляя ранее сохранённые контактные данные покупателя.

#### Оформление заказа

После отправки формы контактных данных презентер получает данные покупателя и содержимое корзины, и формирует объект `IOrderRequest`.

В объект заказа входят:
- способ оплаты;
- адрес доставки;
- email;
- телефон;
- итоговая стоимость корзины;
- массив идентификаторов выбранных товаров.

Сформированный заказ передаётся в `ApiService` для отправки на сервер.

После успешного ответа сервера презентер:
- очищает модель `Cart`;
- очищает модель `Buyer`;
- отображает компонент `OrderSuccess` с итоговой суммой заказа.

При закрытии сообщения об успешном оформлении заказа презентер закрывает модальное окно.

Ошибки при отправке заказа выводятся в консоль и не приводят к очистке данных корзины и покупателя.

#### Загрузка каталога

При инициализации приложения презентер выполняет запрос каталога через `ApiService`.

После получения ответа массив товаров сохраняется в модели `Products`. Изменение модели генерирует событие `catalog:changed`, после чего презентер создаёт карточки товаров и отображает каталог.

При ошибке загрузки каталога информация об ошибке выводится в консоль.
